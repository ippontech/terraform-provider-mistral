# Mistral AI Provider

The Mistral AI provider manages objects of [Mistral AI](https://mistral.ai) with Terraform or OpenTofu:

- in a workspace, with a standard API key: agents, libraries and their documents, connectors, prompts, skills and service accounts;
- in an organization, with an Admin API key: workspaces, API keys, invites, user groups and the spend limit. The Admin API is available on Enterprise plans only, and Mistral grants access to it on request.

Most of these endpoints are in public preview at Mistral: their fields can change without a deprecation period. The page of each resource and data source says whether it is in preview and whether it was tested against the live API.

The provider needs Terraform or OpenTofu 1.11 or later.

## Example Usage

```terraform
terraform {
  required_version = ">= 1.11"

  required_providers {
    mistral = {
      source  = "ippontech/mistral"
      version = "~> 0.1"
    }
  }
}

# Credentials come from the environment: MISTRAL_API_KEY for the workspace
# resources, MISTRAL_ADMIN_API_KEY for the Admin API ones.
provider "mistral" {}
```

## Authentication

A standard API key is scoped to the workspace it was created in: every resource of the provider configuration acts in that workspace. To manage several workspaces, configure one aliased provider block per workspace, each with its own key.

```terraform
# A standard API key acts in the workspace it was created in: manage two
# workspaces with two aliased provider blocks, one key each.
provider "mistral" {
  alias   = "production"
  api_key = var.production_api_key
}

provider "mistral" {
  alias   = "staging"
  api_key = var.staging_api_key
}

variable "production_api_key" {
  type      = string
  sensitive = true
  ephemeral = true
}

variable "staging_api_key" {
  type      = string
  sensitive = true
  ephemeral = true
}
```

Set the credentials with the `MISTRAL_API_KEY` and `MISTRAL_ADMIN_API_KEY` environment variables, or with ephemeral variables on Terraform 1.10 and later. A value set in the provider block from an ordinary variable, even a sensitive one, can be kept in a saved plan.

A provider argument must be known at plan time: a workspace and its key created in one apply cannot configure another provider block in that same apply.

## Schema

### Optional

- `admin_api_key` (String, Sensitive) An Admin API key, tied to one organization, for the Admin API resources and data sources (workspaces, API keys, invites, user groups, spend limit). The Admin API is available on Enterprise plans only, and the key is created in the Admin Panel. Prefer the MISTRAL_ADMIN_API_KEY environment variable: a value set here, even from a sensitive variable, can be kept in a saved plan.
- `api_key` (String, Sensitive) A standard Mistral API key, scoped to the workspace it was created in, for every resource and data source outside the Admin API. Prefer the MISTRAL_API_KEY environment variable: a value set here, even from a sensitive variable, can be kept in a saved plan.
- `server_url` (String) The API base URL, `https://api.mistral.ai` by default. It must use HTTPS, except on a loopback address. Can also be set with the MISTRAL_SERVER_URL environment variable.
