# mistral_user (Data Source)

Reads a member of the organization by email address, with the Admin API key (`admin_api_key`), for the user ID that workspace and user group memberships take. The Admin API needs an Enterprise plan and access granted by Mistral.

-> **Public preview at Mistral.** The Admin API is in public preview: Mistral can change its fields without a deprecation period, and following them may take a new release of the provider.

~> **Not verified against the live API.** This data source is tested against a fake of the Mistral API written from Mistral's documentation. No acceptance test has run against a Mistral organization yet: please report any difference with the live API in an issue.

The lookup ignores case, and `email` keeps the value you set. The read fails when no member has the address; when the address has a pending invite, the error says so, since the person becomes a member only once they accept it.

The roles come back as the API returns them: role UUIDs, which the `mistral_roles` data source names, or legacy letters: `A` for admin and `M` for member, as Mistral documents them, and `B`, which Mistral does not document (the billing manager, by our reading).

## Example Usage

```terraform
data "mistral_user" "ada" {
  email = "ada@example.com"
}

output "ada_user_id" {
  description = "The user ID of Ada, which workspace and user group memberships take."
  value       = data.mistral_user.ada.id
}
```
