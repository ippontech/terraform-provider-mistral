# mistral_assignable_service_account_roles (Data Source)

Lists the workspace roles that a service account can hold, with the standard API key (`api_key`). Their IDs are what the `role_ids` of `mistral_service_account` take.

-> **Public preview at Mistral.** The Service Accounts API is in public preview: Mistral can change its fields without a deprecation period, and following them may take a new release of the provider.

~> **Not verified against the live API.** This data source is tested against a fake of the Mistral API written from Mistral's documentation. No acceptance test has run against a Mistral organization yet: please report any difference with the live API in an issue.

These are the roles of one workspace, from the service accounts API. The organization roles of the Admin API are another list. Set `workspace_id` to the workspace of the provider's API key; the owner of the key needs the Workspace admin role (`workspace_admin`) on it.

Filter the list with a `for` expression on `name`, as in the example of `mistral_service_account`. Whether `name` holds the API name of a role, such as `workflow_executor`, or its label in the Admin Console is not verified.

## Example Usage

```terraform
data "mistral_assignable_service_account_roles" "this" {
  workspace_id = "5d3c4c7e-1f0a-4b8e-9c61-0a6f3e2b9d10"
}

output "assignable_role_ids" {
  description = "The IDs of the roles a service account of the workspace can hold, grouped by role name."
  value       = { for r in data.mistral_assignable_service_account_roles.this.roles : r.name => r.id... }
}
```
