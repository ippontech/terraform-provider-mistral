# mistral_skill (Resource)

Manages a skill of the workspace of the standard API key (`api_key`): versioned instructions, with a description that tells the model when to use them and the files they need.

-> **Public preview at Mistral.** The Skills API is in public preview: Mistral can change its fields without a deprecation period, and following them may take a new release of the provider.

~> **Not verified against the live API.** This resource is tested against a fake of the Mistral API written from Mistral's documentation. No acceptance test has run against a Mistral organization yet: please report any difference with the live API in an issue.

## Versions

A change of `description`, `body` or `assets` creates a new version of the skill, which becomes its latest version; `version` gives its number. Any other change creates no version: a change of the sharing settings updates the skill, and a change of `notes` alone updates the notes of the latest version. When one apply does both, the version comes first.

Mistral keeps every version and none can be deleted: destroying the resource deletes the skill with all its versions. A version created in Studio shows as drift on the next plan, and the apply writes the configuration back as one more version.

Mistral deduplicates a definition it already holds, and the documentation does not say whether it compares it with the latest version only or with every version. If it matches the configuration to an earlier version, the latest version keeps another definition and the apply fails with that reason: change the definition, even slightly, so that Mistral creates a new version.

## Assets

`assets` maps a file name to its content: `content` for a text file, with `file`, and `content_base64` for a binary file, with `filebase64`. The files travel in the request body, so the plan and the state hold their content. When the API returns the same bytes in another form, as bytes for a text file or in another base64 alphabet, the state keeps the configured value.

## Name

The API cannot rename a skill: changing `name` replaces it. The new skill starts again from a first version, without the versions or the aliases of the old one.

## Sharing

`sharing_scope` defaults to `private`. With `workspace`, `workspace_relation` sets the access of the members of the workspace, `writer` by default. The API does not return `workspace_relation`: the state keeps the configured value, a change made in Studio does not show as drift, and an import leaves it unset, so the first apply after an import sets it.

## Not managed yet

The aliases that name a version are not managed by this resource: an update leaves them where they are.

## Example Usage

```terraform
resource "mistral_skill" "extract_invoices" {
  name        = "extract-invoices"
  description = "Use it to read the totals of an invoice in PDF."
  body        = <<-EOT
    Run scripts/extract.py on the invoice, then answer with its totals.
    Convert them to euros with the rates of data/rates.csv.gz.
  EOT

  assets = {
    # A text file: content, such as file("skill/extract.py").
    "scripts/extract.py" = {
      content    = <<-EOT
        import sys
        print(open(sys.argv[1], "rb").read()[:100])
      EOT
      executable = true
    }
    # A binary file: content_base64, such as filebase64("skill/logo.png").
    "data/rates.csv.gz" = {
      content_base64 = base64gzip("currency,rate\nUSD,1.08\n")
    }
  }

  notes = "Convert the totals to euros"
}
```

## Schema

### Required

- `name` (String) The name of the skill. The API cannot rename a skill: changing it replaces the skill, and the new one starts again from a first version.

### Optional

- `assets` (Attributes Map) The additional files of the skill, by file name. Each one sets either `content` or `content_base64`. Changing them creates a new version. The state holds their content. (see [below for nested schema](#nestedatt--assets))
- `body` (String) The body of the skill: the instructions the model follows when it uses the skill. Changing it creates a new version.
- `description` (String) The description the model reads to decide when and how to use the skill. Changing it creates a new version.
- `notes` (String) Notes on the latest version. A change of the description, body or assets sends them with the new version; a change of the notes alone updates the notes of the latest version and creates no version.
- `sharing_scope` (String) Who can use the skill: `private` (the default) keeps it unshared, `workspace` shares it with every member of the workspace.
- `workspace_relation` (String) The access every member of the workspace gets when `sharing_scope` is `workspace`: `writer` (the default) or `reader`. It is refused with any other scope. The API does not return it, so the state keeps the configured value and an import leaves it unset.

### Read-Only

- `created_at` (String) When the skill was created, in RFC 3339 format.
- `id` (String) The skill ID.
- `updated_at` (String) When the skill was last updated, in RFC 3339 format.
- `version` (Number) The latest version of the skill, the one Mistral returns when no version is asked for. A change of `description`, `body` or `assets` creates a new version; any other change keeps it.

### Nested Schema for `assets`

Optional:

- `content` (String) The content of a text file, such as `file("scripts/extract.py")`.
- `content_base64` (String) The content of a binary file, base64-encoded, such as `filebase64("assets/logo.png")`.
- `executable` (Boolean) Whether the file is executable. Defaults to `false`.

## Import

In Terraform 1.12 and later, an `import` block can use the resource identity:

```terraform
import {
  to = mistral_skill.extract_invoices
  identity = {
    id = "5c8e2a1f-3b7d-4c9e-8f6a-1d2b3c4e5f60"
  }
}
```
