# mistral_connector_credential (Resource)

Manages a named set of credentials of a connector, with the standard API key (`api_key`): the bearer token, headers or OAuth2 client credentials that Mistral sends to the connector server for the members of a workspace or of the organization.

-> **Public preview at Mistral.** The Connectors API is in public preview: Mistral can change its fields without a deprecation period, and following them may take a new release of the provider.

~> **Not verified against the live API.** This resource is tested against a fake of the Mistral API written from Mistral's documentation. No acceptance test has run against a Mistral organization yet: please report any difference with the live API in an issue.

## Secrets

`credentials_wo` is a write-only argument: Terraform sends it to the API and never stores it in the plan or the state, and the API never returns it. It needs Terraform 1.11 or later, and accepts an ephemeral value. Write it with `jsonencode`, with one of these fields:

- `bearer_token`: a token for a connector that authenticates with a bearer token;
- `headers`: an object of header names and values. `jsonencode({ headers = {} })` connects a server that needs no credentials, as the Mistral guide does;
- `oauth`: OAuth2 client credentials (`grant_type = "client_credentials"`, `client_id`, `client_secret`, or `client_certificate` and `client_private_key`).

Since Terraform cannot compare a write-only value, a change of `credentials_wo` alone plans nothing. Change `credentials_wo_version` to send the new value. A change of `title` or `is_default` alone updates the credentials without sending the secret again.

## Scopes

`scope` is `workspace` for the members of the workspace of the API key, or `organization`. The `user` scope of the API is not supported: it binds the credentials to the person who owns the API key, which a configuration shared by a team rarely wants.

When the connector stops being shared with the workspace or the organization, the API removes the credentials of that scope. The next plan then creates them again.

## Defaults

The first credentials of an authentication method become its default. When `is_default` is left out, the API decides, and the provider reads what it decided. `is_default = true` makes these credentials the default and demotes the previous one. The API refuses `is_default = false` for the current default: promote other credentials first.

## Existing credentials

The create checks that the connector has no credentials by that name in the scope. If it has, the create fails and gives the `import` block that brings them under Terraform. The import cannot recover the secret: the state of an imported resource has no `credentials_wo_version`, so the first apply after the import sends `credentials_wo`.

## Example Usage

```terraform
variable "orders_api_key" {
  description = "The API key of the orders MCP server."
  type        = string
  sensitive   = true
  ephemeral   = true
}

resource "mistral_connector" "orders" {
  name        = "orders"
  description = "Looks up orders and their status."
  server      = "https://orders.example.com/mcp"
  visibility  = "shared_workspace"
}

resource "mistral_connector_credential" "orders" {
  connector_id = mistral_connector.orders.id
  scope        = "workspace"
  name         = "production"
  title        = "Production API key"

  credentials_wo = jsonencode({
    headers = { "X-Api-Key" = var.orders_api_key }
  })
  # Raise it after a rotation of the key, to send the new one.
  credentials_wo_version = 1
}
```

## Schema

### Required

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `connector_id` (String) The ID of the connector, such as `mistral_connector.this.id`. Changing it replaces the credentials.
- `credentials_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The secret values, as a JSON object written with `jsonencode`: `bearer_token` (a string), `headers` (an object of strings), or `oauth` (OAuth2 client credentials). Write-only: Terraform sends it on create, and on update when `credentials_wo_version` changes.
- `name` (String) The name of the credentials, unique per connector and scope: up to 64 letters, digits, underscores and dashes. Changing it replaces the credentials.
- `scope` (String) Who the credentials serve: `workspace` (the members of the workspace of the API key) or `organization`. Changing it replaces the credentials.

### Optional

- `credentials_wo_version` (Number) Change it to send `credentials_wo` again, after a rotation of the secret.
- `is_default` (Boolean) Whether these are the default credentials of their authentication method. When unset, the API decides: the first credentials of a method become its default. `true` makes them the default; `false` is refused for the current default.
- `title` (String) A human-readable title, up to 255 characters.

### Read-Only

- `authentication_type` (String) The authentication method the credentials are for, as the API reports it: `oauth2`, `bearer`, `none`, `github_app` or `slack_app`.
- `id` (String) `<connector_id>:<scope>:<name>`.

## Import

In Terraform 1.12 and later, an `import` block can use the resource identity:

```terraform
import {
  to = mistral_connector_credential.orders
  identity = {
    connector_id = "0198e70f-57b0-77f6-a752-0a7f5ea2da35"
    scope        = "workspace"
    name         = "production"
  }
}
```
