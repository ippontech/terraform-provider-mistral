# mistral_user_group (Resource)

Manages a user group of the organization with the Admin API key (`admin_api_key`). A group bundles users so that they get roles together: an organization role, and roles in the workspaces the group is assigned to with `mistral_user_group_workspace`. The Admin API needs an Enterprise plan and access granted by Mistral.

-> **Public preview at Mistral.** The Admin API is in public preview: Mistral can change its fields without a deprecation period, and following them may take a new release of the provider.

~> **Not verified against the live API.** This resource is tested against a fake of the Mistral API written from Mistral's documentation. No acceptance test has run against a Mistral organization yet: please report any difference with the live API in an issue.

## Nested groups

A group names the groups it sits inside with `parent_group_ids`. The API can also set the children of a group, but the provider does not offer it: each nesting then belongs to one resource only, the child's, and two resources never disagree about it. A child added to a group outside Terraform shows as a change of that child, if Terraform manages it.

## Organization role

`organization_role` is the organization role that the group gives its members: `member`, `billing_manager` or `organization_admin`. The API cannot clear it. When the argument is left out, Terraform does not manage the role, and removing the argument leaves the role as it is. To lower it, set `member`.

## Groups an identity provider manages

When the organization syncs users and groups from an identity provider (SSO, or SCIM provisioning, which Mistral announces as not yet generally available), the synced groups are externally managed: `externally_managed` is `true`. The identity provider is the source of truth for their identity, membership and lifecycle, and Mistral refuses changes to the fields it owns. The documentation says no more. Our reading:

- Do not manage a synced group with this resource. Read it with the `mistral_user_group` data source instead, and give it access to workspaces with `mistral_user_group_workspace`.
- The members of a synced group belong to the identity provider. A sync of memberships can remove a member that `mistral_user_group_member` added, and the next apply adds it back.
- An on-demand SCIM sync can delete the "Organization groups that are absent from the SCIM provider". Whether that includes groups created with Terraform is not documented. If it does, the next plan creates the group again, with its members and workspace assignments.

## Destroy

Destroying the resource deletes the group. Its members stay in the organization and lose the roles the group gave them, unless they also hold those roles directly or through another group.

## Example Usage

```terraform
resource "mistral_user_group" "staff" {
  name        = "Staff"
  description = "Every employee of the company"
}

# Nested inside Staff. Its members get the member role in the organization.
resource "mistral_user_group" "interns" {
  name              = "Interns"
  description       = "Summer interns"
  parent_group_ids  = [mistral_user_group.staff.id]
  organization_role = "member"
}
```

## Schema

### Required

- `name` (String) The name of the group, up to 255 characters.

### Optional

- `description` (String) The description of the group, up to 255 characters. Removing it clears the description.
- `organization_role` (String) The organization role the group gives its members: `member`, `billing_manager` or `organization_admin`. When it is left out, Terraform does not manage the role. The API cannot clear a role: removing the argument leaves the role as it is, and `member` is the lowest one.
- `parent_group_ids` (Set of String) The IDs of the groups this group is directly nested inside. Removing one takes the group out of that parent; removing the argument makes it a top-level group.

### Read-Only

- `externally_managed` (Boolean) Whether an identity provider manages the group, through SSO or SCIM. The fields the identity provider owns cannot be changed in Mistral.
- `id` (String) The user group ID, a UUID.

## Import

In Terraform 1.12 and later, an `import` block can use the resource identity:

```terraform
import {
  to = mistral_user_group.interns
  identity = {
    id = "3f2b8c1e-5a4d-4e7f-9b6a-1c2d3e4f5a6b"
  }
}
```
