# mistral_user_group_member (Resource)

Adds a user of the organization to a user group with the Admin API key (`admin_api_key`). The user gets the roles of the group: its organization role, and its roles in the workspaces it is assigned to. The Admin API needs an Enterprise plan and access granted by Mistral.

-> **Public preview at Mistral.** The Admin API is in public preview: Mistral can change its fields without a deprecation period, and following them may take a new release of the provider.

~> **Not verified against the live API.** This resource is tested against a fake of the Mistral API written from Mistral's documentation. No acceptance test has run against a Mistral organization yet: please report any difference with the live API in an issue.

Each resource is one user in one group, so that every membership is added and removed on its own. Use `for_each` for several users. There is no update: changing `group_id` or `user_id` removes the user from the group and adds the new one.

The API adds a user who is already in the group without an error. To avoid taking over a membership made outside Terraform, the create fails when the user is already in the group, and gives the `import` block that brings it under Terraform.

The API has no read of one member: every refresh lists the members of the group, page by page, until it finds the user.

Destroying the resource removes the user from the group, not from the organization. The user loses the roles the group gave, unless they also hold them directly or through another group.

When an identity provider syncs the group (`externally_managed` on the group), it owns the membership: a sync can remove a member that this resource added, and the next apply adds it back. See `mistral_user_group`.

## Example Usage

```terraform
resource "mistral_user_group" "interns" {
  name = "Interns"
}

# One resource per user: each membership is added and removed on its own.
resource "mistral_user_group_member" "interns" {
  for_each = toset([
    "8d1e2f3a-4b5c-4d6e-8f7a-9b0c1d2e3f4a",
    "9e2f3a4b-5c6d-4e7f-9a8b-0c1d2e3f4a5b",
  ])

  group_id = mistral_user_group.interns.id
  user_id  = each.value
}
```

## Schema

### Required

- `group_id` (String) The ID of the user group. Changing it moves the user to another group.
- `user_id` (String) The ID of the user, a member of the organization. Changing it replaces the member.

### Read-Only

- `id` (String) `<group_id>:<user_id>`.

## Import

In Terraform 1.12 and later, an `import` block can use the resource identity:

```terraform
import {
  to = mistral_user_group_member.interns["8d1e2f3a-4b5c-4d6e-8f7a-9b0c1d2e3f4a"]
  identity = {
    group_id = "3f2b8c1e-5a4d-4e7f-9b6a-1c2d3e4f5a6b"
    user_id  = "8d1e2f3a-4b5c-4d6e-8f7a-9b0c1d2e3f4a"
  }
}
```
