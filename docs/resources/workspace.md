# mistral_workspace (Resource)

Manages a workspace of the organization, its name, description and icon, with the Admin API key (`admin_api_key`). The Admin API needs an Enterprise plan and access granted by Mistral.

-> **Public preview at Mistral.** The Admin API is in public preview: Mistral can change its fields without a deprecation period, and following them may take a new release of the provider.

~> **Not verified against the live API.** This resource is tested against a fake of the Mistral API written from Mistral's documentation. No acceptance test has run against a Mistral organization yet: please report any difference with the live API in an issue.

## Destroy archives the workspace

The Admin API has no delete for a workspace: destroying the resource archives it. Mistral documents that archiving makes the workspace unavailable to all its members and that it cannot be undone. The documentation does not say what becomes of the API keys, agents, libraries and other resources of an archived workspace: treat them as lost. Protect a workspace in use with `prevent_destroy`, as in the example.

The default workspace of the organization cannot be archived, so destroying it fails. To stop managing it, remove it from the state with a `removed` block and `destroy = false`.

## Replacement

No argument replaces the workspace: `name`, `description` and `icon` update in place, and the next section covers the other two. A replacement still happens with `terraform apply -replace` or a tainted resource, and it archives the workspace with everything it holds before it creates an empty one.

## Arguments used at creation only

The API takes `admin_user_id` and `add_all_org_members` when it creates the workspace, and never returns them. Replacing the workspace for them would archive it, so a later change plans an in-place update that records the new value in the state, with a warning, and changes nothing at Mistral. Manage who belongs to the workspace, and with which roles, with `mistral_workspace_member`.

- The `admin_user_id` user becomes a member with the Workspace Admin role: a `mistral_workspace_member` for that user must be imported, not created.
- `add_all_org_members` makes every member of the organization a member of the workspace. Terraform does not manage these memberships.

After an import, `admin_user_id` is null: the first apply records the configured value without calling the API.

## Changes outside Terraform

A workspace renamed in the Admin Panel shows as drift, and the next apply renames it back. A workspace archived outside Terraform is removed from the state with a warning, since an archived workspace serves nothing: the next apply creates a new workspace. Workspace names are unique in an organization; whether an archived workspace keeps its name is not documented.

## Example Usage

```terraform
variable "admin_user_id" {
  description = "The ID of the user who administers the new workspace."
  type        = string
}

resource "mistral_workspace" "ml" {
  name          = "ML Research"
  description   = "Models and experiments of the research team"
  icon          = "🧪"
  admin_user_id = var.admin_user_id

  # Destroying or replacing the workspace archives it, with everything it
  # holds, and an archived workspace cannot be restored.
  lifecycle {
    prevent_destroy = true
  }
}
```

## Schema

### Required

- `admin_user_id` (String) The ID of the user who gets the Workspace Admin role when the workspace is created. The API takes it at creation only: changing it later records the new value in the state, with a warning, and changes nothing at Mistral.
- `name` (String) The name of the workspace, unique in the organization, of at most 255 characters.

### Optional

- `add_all_org_members` (Boolean) Whether the create adds every member of the organization to the workspace. Defaults to `false`. The API takes it at creation only: changing it later records the new value in the state, with a warning, and changes nothing at Mistral.
- `description` (String) The description of the workspace, of at most 255 characters. Defaults to `""`, as at the API.
- `icon` (String) The icon of the workspace, of at most 2 characters, whose format the documentation does not describe. Defaults to `""`, as at the API.

### Read-Only

- `id` (String) The workspace ID, a UUID.
- `is_default` (Boolean) Whether this is the default workspace of the organization, which cannot be archived.

## Import

In Terraform and OpenTofu 1.12 and later, an `import` block can use the resource identity:

```terraform
import {
  to = mistral_workspace.ml
  identity = {
    id = "8f3c2a1e-5b7d-4c9e-a0f1-2b3c4d5e6f70"
  }
}
```
