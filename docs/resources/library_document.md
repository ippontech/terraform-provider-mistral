# mistral_library_document (Resource)

Uploads a local file to a library as a document, with the standard API key (`api_key`), and waits until the library has processed it, so that an agent can search it.

-> **Public preview at Mistral.** The Libraries API is in public preview: Mistral can change its fields without a deprecation period, and following them may take a new release of the provider.

~> **Not verified against the live API.** This resource is tested against a fake of the Mistral API written from Mistral's documentation. No acceptance test has run against a Mistral organization yet: please report any difference with the live API in an issue.

## A curated corpus

This resource is meant for a curated corpus: a few dozen documents kept in git next to the configuration, and reviewed like code. Each document is one resource, and the state holds the path and the hash of its file, not its content. It is not meant for a bulk ingestion of thousands of files, or of files that change every day: upload those with the API or in AI Studio.

## Content and metadata

The API cannot change the content of a document. A new `source`, or a new `source_hash`, replaces the document: the provider deletes it and uploads the file again, which the library processes, and bills, again. Terraform does not read the file to plan: set `source_hash = filesha256(...)`, or a change of the content goes unnoticed. `size` is the size the API reports; it is not compared with the local file, since a hash catches every change and a size does not.

`name`, `attributes` and `expires_at` change in place. `name` defaults to the file name of `source`. `attributes` holds strings: a value set outside Terraform as another JSON type, such as a number, reads as its JSON text, and an update sends it back as a string.

## Processing

The upload queues the document for processing: text extraction, and OCR for a scanned document. The create waits until the processing ends, for at most `timeouts.create` (20 minutes by default). A processing that fails (status `error`, or `missing_content` when no text was found) or that runs out of time fails the apply. The document stays in the state as tainted, and the next apply deletes it and uploads the file again.

## Same content

A library holds one document per content: the upload of a file the library already holds returns the existing document. The create then fails, and gives the `import` block of that document, rather than managing a document uploaded outside Terraform or by another resource.

## Expiry

The API deletes a document once its `expires_at` has passed. The document then reads as gone, and the next plan uploads it again, unless the configuration sets that `expires_at`: a plan that would upload a document with an expiry in the past fails. Move `expires_at`, or remove the resource.

## Example Usage

```terraform
resource "mistral_library" "support" {
  name = "support-docs"
}

# Every Markdown and PDF file of docs/, kept in git next to the configuration.
# source_hash replaces a document whose file changed.
resource "mistral_library_document" "docs" {
  for_each = fileset("${path.module}/docs", "*.{md,pdf}")

  library_id  = mistral_library.support.id
  source      = "${path.module}/docs/${each.value}"
  source_hash = filesha256("${path.module}/docs/${each.value}")
  attributes  = { team = "support" }

  timeouts {
    create = "30m"
  }
}
```

## Schema

### Required

- `library_id` (String) The ID of the library. Changing it replaces the document.
- `source` (String) The path of the local file to upload, such as `"${path.module}/docs/pricing.pdf"`. Changing it replaces the document, since the API cannot change the content of a document.

### Optional

- `attributes` (Map of String) Free-form string attributes of the document. A value set outside Terraform as another JSON type reads as its JSON text.
- `expires_at` (String) When the API deletes the document, in RFC 3339 format, such as `2027-01-01T00:00:00Z`. Once it has passed, the document reads as gone, and a plan that would upload it again fails until `expires_at` moves.
- `name` (String) The name of the document. Defaults to the file name of `source`.
- `source_hash` (String) A hash of the file, such as `filesha256("${path.module}/docs/pricing.pdf")`. Set it so that a change of the content of the file replaces the document: Terraform does not read the file otherwise.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `created_at` (String) When the document was uploaded, in RFC 3339 format.
- `document_id` (String) The document ID, a UUID.
- `extension` (String) The extension of the document, such as `pdf`.
- `id` (String) `<library_id>:<document_id>`.
- `last_processed_at` (String) When the library last processed the document, in RFC 3339 format.
- `mime_type` (String) The media type of the document, such as `application/pdf`.
- `number_of_pages` (Number) The number of pages the processing found, when the format has pages.
- `process_status` (String) The processing status: `done` once the document can be searched.
- `size` (Number) The size of the document, as the API reports it. It is not compared with the local file: set `source_hash` to follow the content.

## Import

The API does not return the file. After an import, `source` and `source_hash` are null in the state, and the next apply records them in place, without an upload. From then on, a new file replaces the document.

In Terraform 1.12 and later, an `import` block can use the resource identity:

```terraform
import {
  to = mistral_library_document.docs["returns.md"]
  identity = {
    library_id  = "0197f425-5e85-7353-b8e7-e8b974b9c613"
    document_id = "424fdcb8-3c11-478c-a651-9637be8b4fc4"
  }
}
```
