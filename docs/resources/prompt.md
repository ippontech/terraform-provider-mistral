# mistral_prompt (Resource)

Manages a prompt of the workspace of the standard API key (`api_key`): a versioned template, with `{{variable}}` placeholders, that applications fetch from the [prompt registry](https://docs.mistral.ai/studio/conversations/chat-completion/prompt-registry) and use as a system message.

-> **Public preview at Mistral.** The Prompts API is in public preview: Mistral can change its fields without a deprecation period, and following them may take a new release of the provider.

~> **Not verified against the live API.** This resource is tested against a fake of the Mistral API written from Mistral's documentation. No acceptance test has run against a Mistral organization yet: please report any difference with the live API in an issue.

## Versions

A change of `content` or `variables` creates a new version of the prompt, which becomes its latest version; `version` gives its number. Any other change creates no version: a change of `title`, `description` or the sharing settings updates the prompt, and a change of `notes` alone updates the notes of the latest version. When one apply does both, the version comes first.

An application reads the latest version by default, or pins a version number or an alias. Mistral keeps every version and none can be deleted: destroying the resource deletes the prompt with all its versions.

A version created in Studio shows as drift on the next plan, and the apply writes the configuration back as one more version.

Mistral deduplicates a definition it already holds, and the documentation does not say whether it compares it with the latest version only or with every version. If it matches the configuration to an earlier version, the latest version keeps another definition and the apply fails with that reason: change the template, even slightly, so that Mistral creates a new version.

## Name

The API cannot rename a prompt: changing `name` replaces it. The new prompt starts again from a first version, without the versions or the aliases of the old one.

## Sharing

`sharing_scope` defaults to `private`. With `workspace`, `workspace_relation` sets the access of the members of the workspace, `writer` by default. The API does not return `workspace_relation`: the state keeps the configured value, a change made in Studio does not show as drift, and an import leaves it unset, so the first apply after an import sets it.

## Not managed yet

The aliases that name a version, such as `production`, are not managed by this resource: an update leaves them where they are.

## Example Usage

```terraform
resource "mistral_prompt" "coding_assistant" {
  name        = "coding-assistant"
  title       = "Coding assistant"
  description = "System prompt of the code review bot."
  content     = "You are a coding assistant. You specialise in {{language}}."
  variables   = [{ name = "language" }]
  notes       = "Specialise by language"

  # Members of the workspace can use the prompt in Studio, not change it.
  sharing_scope      = "workspace"
  workspace_relation = "reader"
}

output "coding_assistant_version" {
  description = "The version an application pins with ?version= when it fetches the prompt."
  value       = mistral_prompt.coding_assistant.version
}
```

## Schema

### Required

- `content` (String) The prompt template, with a `{{name}}` placeholder for each variable. Changing it creates a new version.
- `name` (String) The name of the prompt. The API cannot rename a prompt: changing it replaces the prompt, and the new one starts again from a first version.

### Optional

- `description` (String) The display description of the prompt. Changing it creates no version.
- `notes` (String) Notes on the latest version. A change of the template or its variables sends them with the new version; a change of the notes alone updates the notes of the latest version and creates no version.
- `sharing_scope` (String) Who can use the prompt: `private` (the default) keeps it unshared, `workspace` shares it with every member of the workspace.
- `title` (String) The display title of the prompt. Changing it creates no version.
- `variables` (Attributes List) The variables of the template, such as `{ name = "language" }` for `{{language}}`. Changing them creates a new version. (see [below for nested schema](#nestedatt--variables))
- `workspace_relation` (String) The access every member of the workspace gets when `sharing_scope` is `workspace`: `writer` (the default) or `reader`. It is refused with any other scope. The API does not return it, so the state keeps the configured value and an import leaves it unset.

### Read-Only

- `created_at` (String) When the prompt was created, in RFC 3339 format.
- `id` (String) The prompt ID.
- `updated_at` (String) When the prompt was last updated, in RFC 3339 format.
- `version` (Number) The latest version of the prompt, the one Mistral returns when no version is asked for. A change of `content` or `variables` creates a new version; any other change keeps it.

## Import

In Terraform 1.12 and later, an `import` block can use the resource identity:

```terraform
import {
  to = mistral_prompt.coding_assistant
  identity = {
    id = "0b5f3c2e-6d1a-4f8e-9c7b-2a4d6e8f1b3c"
  }
}
```
